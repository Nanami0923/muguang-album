# 暮光相册 · 本地相册与智能轮播

[![Android checks](https://github.com/Nanami0923/muguang-album/actions/workflows/android.yml/badge.svg)](https://github.com/Nanami0923/muguang-album/actions/workflows/android.yml)

面向华为 M5 / HarmonyOS 2.0.0 的本地电子相册。Android 原生 APK，深色 Material 3 界面；最低系统为 Android 7.0 / API 24（遵守 LiteRT 2.2.0 实际要求），支持 arm64-v8a / x86_64，图片和配乐均从用户授权的文件夹读取。

## 安装与使用

当前版本为 0.3.1，可从 [v0.3.1 Release](https://github.com/Nanami0923/muguang-album/releases/tag/v0.3.1) 下载 APK 与 SHA-256 校验文件。本机构建路径为 `dist/暮光相册-v0.3.1.apk`。将 APK 复制到平板，使用系统文件管理打开安装；遇到安装来源提示时按系统正常流程授权。

1. 打开“暮光相册”，点击“选择图片文件夹”。建议照片放在 `Pictures/电子相册` 等独立目录。
2. 扫描完成后点击底栏中央放大的播放按钮，直接启动当前相册幻灯片。第四栏“播放设置”调整停留时间、排序、循环、转场及焦点放大。
3. 点击音乐图标，选择 `Music/相册配乐` 等音乐目录；开启背景音乐，选择顺序循环或随机循环并调整音量。
4. 播放时轻触画面显示控制条，可切换照片、暂停、控制音乐或设置停止倒计时。
5. 在“播放设置 → 定时计划”创建每日／每周计划，再点击“进入展示模式”。计划外可低亮度待机或允许系统熄屏。

原图和音乐只读；移除来源、相册或测试数据只删除应用自己的索引。0.3.0 增加可选视觉 API，默认关闭；启用后仅待 AI 图片的压缩副本发送到配置的服务。没有账号、人物身份识别或视频功能；人脸检测用于主体定位。

## 0.3.1 导航与播放动效

- 底栏依次为相册、AI、居中播放、播放设置、设置；中央按钮只启动当前相册，不进入单独页面。宽屏同样使用五栏底边，图库仍可使用双栏内容。
- AI 配置和队列独立到相册右侧的 AI 栏；通用设置保留外观、展示模式、提醒与存储信息。
- 五种切换动效：渐入渐出、翻页、方块转动、叠层、单面旋转。默认随机轮换，一轮用完五种再打乱，轮次交界避免连续重复；也可固定一种或关闭。
- 切换速度高／中／低分别为 350／700／1200 毫秒。短间隔播放时，实际转场最多占停留时间的一半。
- 启用焦点放大后，高／中／低分别提供 3／6／10 秒预设，可自定义 1～3600 秒。放大完成后保持到换片；时长超过照片停留时间会自动缩短。整体展示、手动焦点及单张缩放覆盖仍优先。
- Room 3→4 增量迁移保留旧相册、目录、计划、AI 结果、手动调整及移除记录。已有关闭转场／缩放的设置继续保留。验证记录见 [0.3.1 开发与测试说明](0.3.1开发与测试说明.md)。

## 图片识别与 AI 配置（0.3.0 引入）

- 本地分别处理真人、动漫人物与非人物主体，新增动漫人体、动漫脸及 U²-NetP 模型；分类、人数和展示方式独立保存。
- 类别文字区分照片、动漫插画、游戏渲染和设计排版；“人物”表示人物主导构图，小人物风景仍可归为景物。
- 底栏 AI：填写完整 HTTPS `/chat/completions` 地址、API 密钥和视觉模型 ID，保存并启用；本地争议图随后自动进入 AI 队列。要求服务兼容 Bearer 鉴权、Base64 图片及非流式视觉返回。
- API 每张图一次完成分类和焦点，已有结果按内容指纹复用；每轮默认最多 50 张，可暂停、取消排队及开始新一轮。数量上限不等于金额上限。
- 超时可能已计费，显示调用结果未知，不自动重发；单张详情可显式重新 AI 识别，手动调整始终优先。
- 详情页可选整体展示；全景不强制局部放大。旧手动分类和焦点通过 Room 2→3 迁移保留。
- 模型来源、接入和接口设计见 [0.3.0 更新方案](0.3.0更新方案.md)，实现差异和验证结果见 [开发与测试说明](0.3.0开发与测试说明.md)。

## 智能照片轮播基础（0.2.x，识别流程已由 0.3.0 扩展）

0.2.3 增加单列／双列预览切换并保存选择，修正选点页原生窗口与保存按钮边界。使用 LiteRT 2.2.0、OpenCV 4.12.0，并在构建时检查 16 KB ELF 和 APK 对齐；最低 API 24，不强行兼容 Android 5.0。

- 导入后先建立可播放索引，再在前台期间的工作线程顺序识别；切后台或锁屏暂停，回到前台继续。文件夹卡片按任务进度显示暂停识别、继续识别、取消识别、重试失败项及全部重识别；识别完成后隐藏暂停和取消操作。
- 分类采用 EfficientNet-B0 FP32 → LiteRT FP32；真实人物继续用 EfficientDet-Lite0 与 libfacedetection。0.3.0 为动漫增加独立 ONNX 检测器，非人物改用学习型主体定位，频谱残差降为辅助。
- 照片库可按内容类别和问题状态筛选；标题、播放卡片和筛选区会随照片一起上划移出。点击缩略图进入详情，在完整构图上点选或拖动准星、手动修改类别；照片与设置可上下滚动，底部固定“取消／保存”。支持 A/B 预览、恢复自动焦点及单张缩放方式，留白点击无效。
- 播放设置可多选类别，选择普通播放、A 完整后放大、B 铺满后放大、自动或混合，以及强度、面积裁剪上限和模糊背景。旧相册默认普通播放；播放控制条提供当前照片选点入口。
- 手动焦点始终优先。重扫比较两次可信自动焦点，距离不超过图像对角线 5% 时保留原点，否则采用新点；不主动监测同名替换，修改时间和大小均未变化时可用“全部重识别”更新。
- 长按图库图片打开操作框，可单张重新识别或删除。重新识别保留手动调整；有争议时按 AI 设置处理，可复用已有 AI 结果。删除只从当前相册移除，原图和其他相册保留，刷新不会重新出现，可从回收站恢复。
- 失效索引进入应用内回收站，首次失效起保留 30 天，期间恢复路径后重扫可还原；到期在前台清理，未运行时下次启动补做。手动移除记录单独保留，避免到期后刷新又出现；原图不移动、不删除。
- 模型全部随 APK 捆绑。上游分类只训练了照片、动漫、渲染三类，对插画和几何设计不能承诺准确；不确定时保留待分类，可手动修正。M5 长时间性能及真实图库效果仍需实机验收。

## 播放规则

- 配乐跟随前台幻灯片。切照片不断歌；暂停幻灯片同时暂停音乐；用户单独暂停音乐后不会因切图被恢复。
- 倒计时按真实经过时间计算，暂停幻灯片不延长倒计时；到时图片和音乐一并停止。
- 计划为左闭右开时间窗；例如周五 `22:00—次日07:00` 的星期属于周五。
- 手动播放优先，无关计划的开始／结束不打断手动会话的图片和配乐。
- 切后台、锁屏、退出和计划待机时停止输出声音；这不是独立的后台音乐播放器。
- 音乐文件无效时静音继续看图；所有图片均不可读时停止整个会话并提示检查来源。
- 冷启动和设备重启不自动出声，需要用户主动播放或进入展示模式。

## 平板适配与当前边界

- 华为 M5 / HarmonyOS 2.0.0 是主要目标设备，实际 Android API 应以平板报告的 `SDK_INT` 为准；本项目尚未在用户的 M5 实机验收。
- 0.2.3 起不再兼容 Android 5.0；M5 应核对实际 SDK_INT 和 CPU ABI。
- Android 12 以下使用固定深色配色；不依赖 Google Play 服务或 HMS 账号。
- 普通应用不能保证在锁屏后准点点亮并越过锁屏。常驻展示需应用留在前台，待机画面并非真正熄屏。
- 后台提醒受系统调度影响，不能用来保证无人值守自动开播。
- 首版需手动刷新目录以纳入新增照片／歌曲；每次启动会检查已保存来源是否仍可访问。
- 图片按显示尺寸采样，默认关闭高成本模糊背景。音乐优先使用 MP3、标准 AAC-LC 或 PCM WAV；其他格式取决于设备解码能力。
- 相册删除会同时删除其关联计划，这是初版的明确行为。将来如需保留计划，可改为停用并重新绑定相册。
- 当前以文件名和修改时间排序；拍摄时间排序、文件监控、照片收藏及更复杂转场未纳入这个可安装初版。

## 开发与构建

环境：JDK 17、Android SDK Platform 36、Build Tools 36、Gradle 8.14.3、AGP 8.13.2、Kotlin/KSP 2.3.0、Python 3。最低系统按模型和依赖的实际要求设置，不覆盖其 minSdk 声明。

在本机 PowerShell 可运行：

```powershell
.\scripts\build.ps1
```

或使用标准 Gradle 命令：

```powershell
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

首次构建需要下载开发依赖及 Android NDK 27.0.12077973 / CMake 3.22.1；这不影响安装后的离线运行。`local.properties` 只保存本机 SDK 路径，不应提交给其他设备。

Windows 中文路径下，JVM 测试输出通过 `gradle/ascii-test-classpath.gradle.kts` 暂存到 Gradle 用户目录的英文路径，以避免 Java 参数文件编码问题；源码与项目位置不变。

设备测试需要安装额外测试 APK；仅包含合成图片与静音 WAV，不读取私人图库：

```powershell
./gradlew.bat :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w com.muguang.album.test/androidx.test.runner.AndroidJUnitRunner
```

测试密钥存储等设置功能时必须使用隔离应用：以 `-PisolatedDeviceTest=true` 构建主 APK 和测试 APK，测试包为 `com.muguang.album.smarttest.test`，不会修改正常安装应用的设置。

## 工程结构

```text
app/src/main/java/com/muguang/album/
  core/          共享模型与仓库接口
  data/          Room、DataStore、SAF 扫描和只读来源管理
  playback/      时间窗、自然排序和本地音乐引擎
  ui/            深色主题、相册、定时和设置页面
  presentation/  全屏照片、音乐控制、倒计时和待机画面
  reminder/      系统提醒与恢复接收器
  AlbumViewModel.kt    图片状态机、会话优先级与联动
  MainActivity.kt      文件夹授权、窗口与生命周期
```

测试记录见 `初版开发与测试说明.md`；详细设计见 `安卓平板电子相册完整方案.md`。

初版使用本机 Android 调试签名生成 APK。保存该签名以便后续覆盖安装；长期发布时再固定正式签名，密钥不放入项目源码。
